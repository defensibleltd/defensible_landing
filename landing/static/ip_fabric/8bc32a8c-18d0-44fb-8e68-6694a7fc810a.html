TL;DR The five moves

Doubling down on the integrity and independence of evidence. Do not chase the AI agent race, underpin it.

  1. Lead with the point of view, not the product. "The autonomous network needs separation of powers." Say it before you say "digital twin." It is the one sentence that helps an anxious buyer decide today. A point of view informs a strategy, which then trickles down.
  2. Reframe "read-only" as the trust catalyst, not a limitation. IP Fabric is structurally incapable of breaking the network, so it is the one platform that can independently verify everything that does. It cannot act upon or amend, therefore it has no conflict of interest.
  3. Own the pre-AI and agent facilitation layer: deterministic data discovery, agent optimized surfaces, and the core, a first-class API. The agent is only as good as the twin; the twin is only as good as the discovery. Make the OpenAPI-specified, read-only API the surface that agents and AI coding assistants discover and build against. MCP is the doorway, not the moat.
  4. Treat MCP and agents as consumption proof points, not a new position. They strengthen the existing value themes. Update the explanation of how you deliver value; do not rewrite what you stand for.
  5. Protect the moat with discipline. The day IP Fabric ships an agent that changes production, it forfeits the independence claim and becomes the undifferentiated middle again. Not acting is the strategy, not a gap.

02 Dunford's newer rule

Positioning is not a feature list, so do not get AI whiplash

Before repositioning anything, apply Dunford's most disciplined recent idea, because it prevents the most expensive mistake in this market: repositioning every quarter. AI capabilities usually change your proof points, not your positioning. A value theme is the enduring outcome you deliver that no alternative can; a feature is what delivers it this quarter. Run IP Fabric's 2026 capabilities through her test and the answer is clarifying.

Agents & "agentic NetOps"Context, not product. The rise of autonomous action is the trend that makes IP Fabric's independence more valuable, not a capability to chase.

Keep the value themes fixed and let each new capability become fresh evidence for them. That discipline is itself an advantage while NetBrain and Forward visibly reinvent their pitch around whatever shipped last.

03 The differentiators

Three evergreen value themes neither rival can claim

Your unique attributes are the things true of you and not the alternatives. Stripped down, IP Fabric has exactly three, and they are evergreen: true before AI, and more valuable as AI arrives.

01

It never alters production

Read-only SSH and API discovery. No SNMP polling agents, no config pushes, no autonomous remediation. NetBrain executes changes and auto-remediates; Forward's stated destination is autonomous execution. IP Fabric is the only one of the three structurally incapable of breaking your network.

02

It is independent of the actor

It is not your automation engine or your AI operator. It feeds them. Usually filed as a weakness ("read-only, hands off via API"); in the AI age it is the whole ballgame.

Caveat: this is a positioning choice, not a law of physics. Ship a workflow builder that acts on the network and the claim weakens. Independence has to be defended deliberately.

03

Its output is evidence, not opinion, as change accelerates

Timestamped, immutable snapshots plus 160+ intent-verification rules produce an auditable record: here is the state at 14:02 before the change that caused the outage, here is what matched design and what did not. A compliance artifact for DORA, NIS2, PCI, ISO: the auditable evidence behind the dashboard, not just the picture on it.

These three are really one idea: IP Fabric is the independent, read-only, evidence-grade system of record for the network. AI does not change that; AI is the reason it finally matters to the buyer.

04 The reframe

Separation of powers for the autonomous network

Both primary competitors conflate two jobs the AI era is about to force apart: knowing the true state of the network, and acting on it. NetBrain and Forward race to make the acting autonomous. That quietly creates a governance problem no CISO has solved: when an AI agent proposes and executes a change, who independently verifies the ground truth it acted on, and who holds the immutable record of what it did?

The actor writes; the verifier only reads. The system that acts and the system that verifies must be independent, exactly as financial controls and change management already work.

The governance gap

You do not want the vendor whose agent makes the change to also be the sole authority on whether the change was correct.

That is the AI agent grading its own homework. Every regulated industry already knows the answer to this pattern: it is called separation of duties.

So IP Fabric's position is not "a better digital twin" and not "our AI is more grounded." Category language, said plainly: Network Assurance as the trust layer for AI-driven operations. Not "digital twin" (Forward's word). Not "agentic NetOps" (NetBrain's word, and it puts IP Fabric on the wrong side of "does it act?"). Assurance, redefined as independent verification rather than observation. It turns the supposed weakness into the reason for trust, and makes the rivals' greatest strength, autonomous action, the very thing that creates demand for an independent referee. You become more necessary as your competitors succeed.

06 The agentic-era focus

A first-class API to deterministic discovery and data, optimized for humans and agents, is still an evergreen moat. MCP is just one doorway.

This is the part of the strategy that most needs sharpening, because the market noise is all MCP and agents, and the real leverage is one layer down. Everyone has an MCP server, so MCP is table stakes. The mature position: do not bet the house on MCP-based agent automation yet. Bet it on the layer underneath, the one agents actually stand on.

09 AIM

New reach, same position

AIM (Application-Infrastructure Mapping) (8.1, feature-flagged, Illumio as the first external data provider) is a textbook case of "strengthen the theme, do not change the position." AIM correlates an application inventory (applications, workloads, interfaces, flows) against the network and cloud model IP Fabric already discovers, so a business application traces to the exact path, devices, and controls it depends on. It consumes application data; it does not own it, and it does not watch live traffic. It models how traffic can flow, deterministically, on the same read-only footing as everything else.

AIM in one breath

Full-stack deterministic data for trustworthy AIOps and Network Assurance.

Connect top-down business services to bottom-up infrastructure using inside-out network verification. Bridge operational gaps by surfacing true application behaviours and critical dependencies across full on-prem and cloud footprints.

How it sits next to APM. APM (Application Performance Monitoring) watches applications from the top down: latency, errors, traces, the user-facing symptom. AIM works the other way, bottom up and inside-out, deterministically mapping the infrastructure and network path an application depends on. They are complementary, not competing: APM tells you an application is slow or failing; AIM rules connectivity, path, and policy in or out as the cause, and hands the network and security teams the exact devices and controls involved. AIM is the deterministic dependency map underneath the APM symptom.

💡

Extends the evidence theme upward

From the network layer into the application and segmentation layer. Show which applications ride a device before you touch it, and which apps a compromised workload can reach across every boundary.

💡

Extends separation of powers to segmentation intent

Illumio's host rules stop being an invisible firewall. AIM places them on the same path as network ACLs and cloud security groups and surfaces where the layers disagree. IP Fabric becomes the independent referee that reconciles intended segmentation against what the path permits. It verifies; it does not enforce.

💡

Holds the honest boundary

AIM is not an APM. It will not tell you why an app is slow; it rules connectivity and policy in or out as the cause. Refusing the adjacent job keeps the position clean, the same discipline as read-only.

The one thing to protect

Consuming Illumio's data read-only and reconciling it is on-position. Pushing segmentation policy back would forfeit the independence claim, exactly as a workflow builder would.

10 The pitch, live

The narrative, and how to fight each one

Open with the insight, not the product.

Every network vendor now promises AI that can diagnose, decide, and act for you. That future is real. But it introduces a problem your auditors will ask about before your engineers do: if an AI agent changes your network, what independent system proves the change was correct, and holds the record of what happened? Most teams' answer today is "the same AI that made the change." No regulated business runs its finances that way, and it cannot run its network that way either.

The missing piece is not a smarter agent. It is an independent system of record that never changes the network, so it can be trusted to verify everything that does. We discover 100% of your estate read-only, model it vendor-neutrally, and check it against 160+ rules and your own intent, on a timestamped record you can hand to an auditor. Every answer traces back to a source. Point your automation, your AI agents, even NetBrain or Forward, at the network; point IP Fabric at the truth. Move fast, and prove you didn't break anything.

That last line steals the clothes off Forward's "Move Fast. Break Nothing." Their slogan promises you won't break things; IP Fabric's job is to prove it, the part their slogan cannot deliver on its own.
Against NetBrainaction & agents

Concede the automation, reframe on governance. "Would you let the same system execute the change and be the sole record of whether it was safe? IP Fabric is read-only by design, so it can verify NetBrain's work without a conflict of interest." Hit the two documented soft spots: modular pricing (roughly 125% jump to add all modules) and SNMP plus Telnet collection weight versus IP Fabric's cleaner CLI/API snapshot.

Against Forwardthe math twin

Do not argue "more accurate," you lose the math fight. Argue independence, time-to-value, fit. Forward Predict's "know before you act" is beta to GA fall 2026, and even at GA it validates proposed changes rather than pushing them; it is priced for the Fortune 500 and federal. IP Fabric ships assurance, compliance evidence, and 160+ rules now, without a query-language learning curve (their own AI Assist exists because NQE is hard), at a size mid-and-upper enterprise can actually deploy.

Against the source-of-truth & legacy tiertier two

Do not fight on price or "we also discover." Fight on the difference between a database of intended state and independent proof of actual state. "A source of truth records what the network should be. IP Fabric proves what it is, read-only, checked against 160+ rules, on a timestamped record. SNMP polling gives an AI stale, partial input; ours is complete and deterministic. Complementary to a source of truth, not a substitute for assurance."

The real moat

Win the pre-AI layer, before a single agent runs

Every AI story assumes the model underneath is complete and correct. It rarely is, and that is where the fight is won. Agentic AI is only as good as the twin beneath it, and the twin is only as good as the discovery beneath that. NetBrain collects through SNMP plus Telnet/SSH polling; stale polling produces a twin the AI reasons over confidently and wrongly. IP Fabric's discovery is read-only SSH and vendor API, vendor-neutral, snapshot-based: it reconstructs actual forwarding state with no SNMP blind spots and nothing written back. Paired with a discoverable, deterministic API, the read-only nature is not just a safety story; it is the foundation the whole AI stack stands on.

APX Appendix

Making the OpenAPI Specification (OAS) discoverable on any installed instance inc. marketing / public demos

The strategy in section 06 depends on one tactical fix: the OpenAPI surface has to be genuinely discoverable and consumable by an agent, not merely published. Today it is published but hard to reach. The findings below were verified against the live marketing instance: https://marketing.ipf.cx, in September 2026.

Check (live, Sep 2026)Result
/api/static/oas/openapi-internal.jsonHTTP 200, application/json, 8.08 MB. Real, complete, and large enough that dumping it whole burns an agent's context. So the documentation has to be agent-readable and selectively consumable, scoped views plus an operation index the agent drills into, never read whole. See move 2 below.
/api/rapidoc/JS shell only. The page loads rapidoc.9.3.4.js and mounts a <rapi-doc> web component (its spec-url is openapi.json). A crawling agent that reads the HTML sees an empty custom element, not the API.
llms.txt, robots.txt, /.well-known/No real file. Each path returns 200 but serves the SPA HTML shell, not a machine-readable index. There is no agent front door.
Directory listing /api/static/oas/Blocked (403). So the only real route to the spec is knowing the exact deep path; nothing links or indexes it.

The spec being published is not the same as an agent being able to find and use it. That is the actionable work, and it is three concrete moves.

  • DoExpose the spec through the MCP, do not just name it. Put the stable OAS URL in the server's instructions/info so the model sees the pointer, but go further: serve the spec as an MCP resource, or a search_operations / describe_operation tool, so an in-session agent pulls the exact contract it needs deterministically, without an 8MB context dump.
  • DoKeep the spec complete; serve scoped views, do not shrink the source. The canonical OAS must stay full-coverage: an incomplete contract defeats determinism. Make it usable by serving tag- or path-scoped sub-specs and a compact operation index (operationId, summary, tag) the agent drills into, plus a static, non-JS rendering (RapiDoc renders via JavaScript, which a crawling agent cannot read).
  • DoPublish an llms.txt as the front door for coding agents. The agent that writes a deterministic pipeline usually never opens the MCP; it reads docs and the web. IP Fabric already nails this for the support matrix: matrix.ipfabric.io/llms.txt is a plain, machine-readable index of every supported vendor and feature across versions, in Markdown, JSON, CSV, and text. Do the same for the platform: one llms.txt pointing at the OAS, the docs, and vendor coverage.
